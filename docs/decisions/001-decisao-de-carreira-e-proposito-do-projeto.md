# 001 — Decisão de carreira e propósito do projeto

**Data:** 05/06/2026  
**Status:** Decidido  
**Contexto:** Este registro documenta as decisões que moldaram este projeto e a transição de carreira que o motivou.

## Histórico

Passei vários anos trabalhando em suporte técnico, atendendo tickets, fazendo triagem de chamados e intermediando a comunicação entre clientes e equipes internas. Com o tempo, comecei a estudar qualidade de software, CTFL, automação de testes com Cypress e os fundamentos do desenvolvimento — para crescer além do suporte.

Criei o SS Tickets como forma de colocar em prática o que eu achava que já sabia e aprender o que ainda não sabia. O domínio era familiar: eu havia vivido o fluxo de gestão de chamados por dentro durante anos. Construir o sistema significou entender a stack completa: backend, frontend, banco de dados, autenticação e testes automatizados.

## A virada

Durante os estudos de qualidade, me deparei com uma vaga de Analista de Processos Jr. Enxerguei não apenas uma oportunidade de emprego, mas uma chance real de sair do suporte e iniciar uma profissão que valoriza a capacidade de mapear, entender e melhorar processos — e, quando necessário, executá-los com as ferramentas de IA certas.

Essa mudança transformou completamente o propósito deste projeto.

## A decisão

Decidi reposicionar o SS Tickets como a consolidação da minha trajetória até aqui:

- **AS IS:** documentar a API existente como um processo real, utilizando notação BPMN 2.0, cenários BDD e tabela de decomposição de atividades.
- **TO BE:** propor e implementar uma evolução estruturada do sistema utilizando o Claude Code como ferramenta de refatoração — não para escrever código que não entendo, mas para aprender lendo o que é produzido e compreendendo cada decisão.
- **Longo prazo:** lançar o SS Tickets como projeto open source para pequenas empresas que precisam de uma solução gratuita e simples de gestão de chamados.

A regra que guiou cada linha de código deste projeto desde o início:

> Todo código que entra neste projeto passa pelo meu entendimento: não necessariamente linha a linha, mas em termos de o que faz, por que existe e como se encaixa no sistema.

## O que este projeto não é

Este não é o portfólio de alguém que quer ser desenvolvedor. É o portfólio de alguém que entende desenvolvimento bem o suficiente para analisá-lo, documentá-lo, melhorá-lo e comunicar sobre ele com clareza.
